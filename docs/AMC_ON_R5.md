# AMC on the RPU: MATLAB → Embedded Coder → R5F

The modulation label of §18 is the one algorithm in this project that is small
enough, and needed often enough, to live on the R5F rather than in the PL. This
page is the integration: where it sits, what it consumes, what it costs, how the
MATLAB becomes code, and what is still unproven.

```
 detections of one frame (from the PL capture path, box 5 of the block diagram)
        │
        │  one 1024-sample complex burst per detection, already carrier-recovered
        ▼
 ┌──────────────────────────────────────────────┐
 │ amc_features()     6 features, one 1024-pt FFT │  ~16 kB of static buffers
 └──────────────────────┬───────────────────────┘
                        ▼
 ┌──────────────────────────────────────────────┐
 │ amc_classify()     nearest class mean, 30 const│  5 distances, no allocation
 └──────────────────────┬───────────────────────┘
                        ▼
        label + margin ──▶ association policy (§19)
                           margin small  → keep the track's previous label
                           margin large  → the label enters cost with weight 1
```

## 1. Why the R5F and not the PL

| Criterion | PL | R5F |
|---|---|---|
| FFT per burst | cheap, but a second FFT engine next to the channelizer | reuses the same 1024-point code as everything else |
| Nearest class mean | 30 multiplies — a waste of a DSP column | trivial |
| Change cadence | re-synthesis for every new class or feature | recompile, or reload the constants |
| Requirements stability | feature set is settled (§18) | but classes will grow (32/64-QAM, APSK, OFDM) |

The PL keeps the fixed, high-rate work (covariance, cross-spectrum, CORDIC
phase). AMC is a few thousand operations per *detection*, not per sample, so the
RPU is the right place — and it is the place where a new modulation class is a
table edit rather than a bitstream.

## 2. What the firmware is

| File | Role | Status |
|---|---|---|
| `firmware/amc_r5/amc.h` | the contract: features, classify, run, labels | — |
| `firmware/amc_r5/amc.c` | the implementation the RPU will link | **verified on the host** |
| `firmware/amc_r5/amc_model.h` | centre, spread, class means — **generated** | regenerated by `scripts/amc_export.py` |
| `firmware/amc_r5/test_amc.c` | host harness over the shared vectors | used by `make amc-port` |
| `matlab_v7/amc_features.m` | the same six features, in MATLAB | written, not run |
| `matlab_v7/classify_modulation.m` | the codegen entry point | written, not run |
| `matlab_v7/amc_model_params.m` | the same constants, **generated** | regenerated |
| `matlab_v7/build_amc_r5.m` | Embedded Coder configuration | written, not run |
| `matlab_v7/verify_amc_vectors.m` | MATLAB against the shared vectors | written, not run |

The generated constants are what keep three implementations from drifting: the
Python model, the C port and the MATLAB source all read the same fit.

## 3. The arithmetic, and why single precision

The Cortex-R5F FPU is single precision only; `double` there is a trap-and-emulate
path that costs tens of cycles per operation. The reference build accumulates in
double so that the host comparison is exact, and `-DAMC_SINGLE_ACC` selects the
all-single build. Measured over 120 bursts spanning 0–20 dB
(`docs/evidence/2026-11-06-phase-interf/amc_port.txt`):

| | double | single |
|---|---|---|
| label agreement with the model | 100 % | **100 %** |
| worst feature error | 7e-7 | **1.4e-5** |
| accuracy against truth | 72.5 % | 72.5 % |
| labels changed by single | — | none |

So the switch to single is free *on these vectors*. It is not a proof that it is
free in general: the margin distribution decides, and a burst near a decision
boundary flips. That is why `amc_classify` returns the margin, and why the policy
uses a vote (§18.4) instead of a fresh label per frame.

## 4. Memory and work, counted

| Item | Size |
|---|---|
| input burst (1024 complex single) | 8 kB |
| static work buffers (4 × 1024 floats) | 16 kB |
| twiddle table (512 complex single) | 4 kB |
| model constants (6 + 6 + 30 floats) | 168 B |
| output (label, margin, features) | 32 B |

Work per burst: 1024-point complex FFT, 1024 `atan2`, 4 `sqrt`, no allocation,
every loop bounded. **Cycles are not measured here**; the R5F deadline is gate
G8c, and until it is run no latency number may be quoted.

## 5. Interfaces on the target

```
 PL (capture path)                    R5F                        R5F
 ─────────────────                    ───                        ───
 4096 x 4 complex  ──DMA──▶  TCM buffer (AMC_MAX_SAMPLES)  ──▶  amc_run()
                                                                    │
 detections (az, bins) ────▶  association state  ◀── label, margin ─┘
```

* The burst must be **carrier-recovered**: §18.2 measured that a residual offset
  of 1e-3 per sample destroys the label for BPSK and QPSK (the fourth-order
  cumulant rotates away). On the RFDC path the residual offset is set by the
  tuning word, so this is a *calibration* requirement, not luck.
* The burst must be **one emitter**: the features assume a single carrier in the
  bin. If the cell holds two, the label describes neither — that is §19's
  verification index job, not AMC's.
* `AMC_MIN_SAMPLES` is 32; §18.3 measured that 64 symbols (256 samples) are
  enough at 10 dB and 8 symbols are not.

## 6. Embedded Coder steps

```bash
python3 scripts/amc_export.py        # regenerate model constants + vectors
python3 scripts/amc_port_check.py    # G8a: the C port must be PASS first
matlab -batch "verify_amc_vectors"   # MATLAB against the same vectors
matlab -batch "build_amc_r5"         # G8b: sources into build/amc_r5_codegen
```

`build_amc_r5.m` configures `coder.config('lib')` with `GenCodeOnly`, target
`ARM Compatible->ARM Cortex-R`, little endian, 32-bit `int`/`long`, 32-bit
`float`, non-finite values disabled, and one fixed-size burst argument
(`single complex [1024 1]`, variable size off). The RPU compile flags used by the
build kit are in the script's closing message:

```
armr5-none-eabi-gcc -mcpu=cortex-r5 -mfloat-abi=hard -mfpu=vfpv3-d16 -O2 \
                    -ffunction-sections -fdata-sections
```

## 7. What is proven, and what is not

**Proven (G8a, host):** the C implementation returns the same label as the model
on every one of 120 bursts, with every feature within 1.4e-5, and the same
accuracy (72.5 %). Single precision changes nothing on that set.

**Not proven:** that Embedded Coder emits equivalent code (G8b); that the library
links and fits the RPU memory (G8b); that a frame meets its deadline on the R5F
(G8c); that the features survive the RFDC's residual carrier in hardware (G5);
that any of it works on a real emitter.

**And the limits that no amount of integration removes:**
* at 0 dB the label is chance — every burst is decided as one class (§18.2);
* two emitters with the same modulation are never separated by AMC (§18.5);
* a decoy that copies the waveform copies the label with it — AMC is an identity
  aid, never an authenticator (§18.6).

## 8. Gate summary

| Gate | Question | Status |

| G8b | MATLAB → Embedded Coder → linkable library | **NOT RUN** |
| G8c | frame deadline on the R5F | **NOT RUN** |
