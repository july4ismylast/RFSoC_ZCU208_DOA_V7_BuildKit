# Simulink Closed-Loop Model Guide

> **V7 note:** Historical MUSIC calculations later in this inherited guide are
> background only. The executable builder uses the realistic 2x2 receiver,
> calibrated WPI + bounded ML/GN + full-attitude unit-vector EKF. The
> illustrated `REALISTIC_DOA_ENGINEERING_GUIDE.md` is authoritative.

This document describes the model generated by `build_3d_doa_simulink.m`. It
is intentionally separate from the scripted MATLAB implementation documented
in `RUN_3D_DOA_SIM_GUIDE.md`.

## 1. Build and run

From MATLAB R2024a, make the extracted project directory current and run:

```matlab
clearvars
rehash path
verify_r2024a_setup
build_3d_doa_simulink
sim('DOA_3D_Homing')
```

The shorter equivalent is:

```matlab
START_HERE
```

`build_3d_doa_simulink` creates `DOA_3D_Homing.slx`. The generated `.slx` is
not the source of truth; rebuild it after editing `sim3d_params.m` or a System
object.

Source selection is profile-based. `sim3d_params.m` passes
`P.Source.ModulationType` to `source_modulation_profile.m`, whose `switch/case`
loads the appropriate LFM, NLFM, PM, digital, or other waveform parameters
before the builder configures `RF_Source_3D`.

## 2. Model purpose

The model simulates a fixed RF source and a moving four-channel receiver. The
receiver performs wideband channelization, energy detection, source-candidate
selection, 3D DOA estimation, and detection-gated pure-pursuit navigation. The
receiver moves toward the source and the Stop Simulation block ends the run
when range is no greater than `P.Nav.ArrivalRadius`.

The default initial geometry is:

```text
RF source:             [500 300 200] m
Moving target/receiver:[  0   0  50] m
Initial range:         602.08 m
Initial body DOA:      azimuth 30.96 deg, elevation 14.43 deg
```

## 3. Top-level signal flow

```text
Delayed pose
    |
    v
RF_Source_3D ---> PFB_Channelizer ---> Spectrum_Est ---> CA_CFAR
      |                                      |              |
      |                                      v              v
      |                                Noise_Floor ---> Bin_Cluster
      |                                                       |
      |                                                       v
      |                                                Candidate_Sel
      |                                                       |
      v                                                       |
Snapshot_Select ---> DOA_Est ---------------------------------+
                         |                                     |
                         v                                     v
               Truth_Error_Monitor                       Platform_3D
                         |                                     |
                         +-- scopes/displays/logs              +-- delayed pose
                                                               +-- stop on arrival
```

## 4. Simulation timing

The Simulink solver is fixed-step discrete:

```text
FixedStep = P.Sim.Dt = 0.1 s
StopTime  = P.Sim.StopTime = 60 s
```

Each navigation update processes one synthetic IQ frame of 8192 complex
samples. At `Fs = 2.048e9` samples/s, that frame represents

```text
8192 / 2.048e9 = 4 microseconds
```

of RF data. The 4 microsecond signal-processing frame is condensed into one
0.1 second navigation update. This is a behavioral closed-loop simulation, not
a real-time clock-cycle model. The separate RFSoC HDL front end uses scalar
sample/valid timing and is described in `FILE_BY_FILE_REFERENCE.md`.

## 5. Block-by-block algorithm

### 5.1 `RF_Source_3D`

Class: `SourceModel3D`

Inputs:

- delayed receiver position `[x y z]`;
- delayed yaw;
- delayed pitch.

Output: `8192 x 4` complex IQ matrix, with rows as time samples and columns as
coherent antenna channels.

Processing:

1. Generate the selected normalized complex-baseband waveform.
2. Calculate source range and body-frame azimuth/elevation.
3. Apply free-space loss at 1 m plus configurable range exponent.
4. Apply the phase delay for each X/Y/Z antenna baseline.
5. Add thermal noise using `k*T*Fs*noiseFigure`.
6. Apply channel gain and phase mismatch.

The non-coplanar four-element geometry is necessary to distinguish positive
from negative elevation.

### 5.2 `PFB_Channelizer`

Class: `PFBFFTChannelizer4`

Four independent but identically configured `dsp.Channelizer` objects process
the four coherent channels. Separate objects avoid mixing channel state while
identical coefficients preserve relative antenna phase.

Default dimensions:

```text
Input:  8192 x 4
Output: 8 x 1024 x 4
```

The frequency-bin spacing is

```text
Delta_f = Fs/NumBands = 2.048 GHz/1024 = 2 MHz.
```

### 5.3 `Spectrum_Est`

Class: `SpectrumEstimator4`

The PFB bins are FFT-shifted so zero baseband frequency is in the middle. Power
is averaged over the eight temporal PFB outputs and across the four receiver
channels. Exponential smoothing is then applied:

```text
P_state[k] = (1-alpha)*P_state[k-1] + alpha*P_current[k]
```

with default `alpha = 0.25`.

Outputs include four-channel power, combined power, dB spectrum, and a
baseband-frequency vector.

### 5.4 `Noise_Floor`

Class: `NoiseFloorEstimator1D`

A sliding median produces a local robust noise estimate for each frequency
bin. The median of the entire combined spectrum produces a scalar global noise
floor. Median estimation is resistant to a limited number of strong occupied
bins.

### 5.5 `CA_CFAR`

Class: `CACFAR1D`

For each cell under test, the algorithm excludes guard cells and averages the
left and right training cells. For `N = 2*TrainCells`, the threshold multiplier
is

```text
alpha = N*(Pfa^(-1/N) - 1).
```

Detection occurs when

```text
P_cell > alpha * mean(training cells).
```

The first and last bins that cannot support full training windows are not
tested.

### 5.6 `Bin_Cluster`

Class: `BinClusterEstimator`

Adjacent detected bins are collected into clusters. Gaps no larger than
`MergeGapBins` can be filled. For every accepted cluster, the block calculates:

- power-weighted center frequency;
- start and stop frequency;
- bandwidth from bin count times bin spacing;
- maximum cluster power in dB.

The output arrays have fixed length `MaxClusters`, which is suitable for a
Simulink System object.

### 5.7 `Candidate_Sel`

Class: `CandidateSelector`

Each cluster must pass configured bandwidth and SNR limits. The score is

```text
score = SNR_dB - 0.05*abs(BW_MHz - 30).
```

The valid candidate with the highest score is selected. `Valid` is passed to
the platform so invalid search results cannot steer navigation.

### 5.8 `Snapshot_Select`

Class: `SnapshotDecimator4`

This branch works on the original coherent IQ channels, not on power. With
`FrameLength = 8192` and `SnapshotStride = 32`, it selects

```text
8192/32 = 256 spatial snapshots.
```

Using many coherent snapshots stabilizes the covariance while keeping MUSIC
scan cost much smaller than processing every raw time sample.

### 5.9 `DOA_Est`

Class: `DOAEstimator4Ch`

The default algorithm is MUSIC. With time snapshots stored in rows and antenna
channels in columns, covariance is deliberately formed as

```text
R = X^T * conj(X) / Ns.
```

This orientation produces the same `exp(-j*k*r.u)` steering-vector convention
as `SourceModel3D`. Using `X^H*X` here would conjugate the array manifold and
mirror the estimated direction.

After eigendecomposition, the dominant eigenvector represents the signal
subspace and the remaining vectors form the noise subspace `E_n`. MUSIC scans
the azimuth/elevation grid with

```text
P_MUSIC(az,el) = 1 / (a^H E_n E_n^H a).
```

The largest pseudospectrum point is returned. The same class also contains
MVDR, single-source 3D ESPRIT, and phase-interferometry modes.

### 5.10 `Truth_Error_Monitor`

Class: `TruthErrorMonitor3D`

This block uses the delayed pose corresponding to the current RF frame. It
calculates true body-frame azimuth/elevation, wrapped azimuth error, elevation
error, and the exact angular separation between estimated and true unit
vectors:

```text
angular_error = acosd(dot(u_est,u_true)).
```

### 5.11 `Platform_3D`

Class: `PlatformDynamics3D`

Inputs are estimated azimuth, estimated elevation, candidate validity, and
source position. With pure pursuit, filtered body-frame DOA becomes the heading
and pitch correction. Azimuth innovation is circularly wrapped to prevent a
false 358-degree jump when crossing the `-180/+180` boundary.

Commands are rate-limited:

```text
abs(yaw rate)   <= MaxTurnRate
abs(pitch rate) <= MaxClimbRate.
```

The position update is

```text
vx = V*cos(pitch)*cos(yaw)
vy = V*cos(pitch)*sin(yaw)
vz = V*sin(pitch)
position[k+1] = position[k] + Dt*[vx vy vz].
```

If detection is invalid, yaw and pitch are held. When range is at or below the
arrival radius, position is held and `Arrived` becomes true.

### 5.12 Unit delays and stop logic

`Delay_Pos`, `Delay_Yaw`, and `Delay_Pitch` break the algebraic loop between the
source geometry and platform motion. `Stop_On_Arrival` receives the platform's
logical arrival output and ends the run immediately after arrival.

## 6. Live outputs inside Simulink

Four Scope blocks open from the model `StartFcn`:

1. `DOA_Estimated_vs_Truth`
2. `DOA_Errors`
3. `Range_and_Arrival`
4. `Detection_and_SNR`

Numeric Display blocks show:

- detection validity;
- arrived state;
- range in metres;
- peak SNR in dB;
- estimated/true azimuth and error;
- estimated/true elevation and error;
- total angular error;
- selected RF center in GHz;
- selected bandwidth in MHz.

## 7. Logged variables

The To Workspace blocks use `Timeseries` format. Important variables are:

| Variable | Contents |
|---|---|
| `log_pos` | Moving receiver position, metres |
| `log_yaw`, `log_pitch`, `log_roll` | Receiver attitude, degrees |
| `log_range`, `log_arrived` | Source range and arrival state |
| `log_doa_az`, `log_doa_el` | Estimated DOA |
| `log_true_az`, `log_true_el` | Ground-truth body DOA |
| `log_az_error`, `log_el_error` | Signed component errors |
| `log_angular_error` | Total 3D separation error |
| `log_candidate_valid` | Search candidate validity |
| `log_fc_hz`, `log_bw_hz` | Selected baseband center and bandwidth |
| `log_signal_peak_db`, `log_snr_db` | Signal peak and estimated SNR |
| `log_spectrum_db`, `log_frequency_hz` | Complete PFB spectrum and frequency axis |

The model `StopFcn` calls `plot_simulink_results`, which converts these logs to
the same common structure used by `plot_homing_results`.

## 8. Final figures

2. range and arrival threshold;
3. detection-valid state and SNR;
4. estimated versus true azimuth;
5. azimuth error;

## 9. Worked first-update example

For the default geometry,

```text
delta = source - receiver = [500 300 150] m
range = sqrt(500^2 + 300^2 + 150^2) = 602.08 m
azimuth = atan2(300,500) = 30.96 deg
elevation = atan2(150,sqrt(500^2+300^2)) = 14.43 deg.
```

At 4 GHz,

```text
lambda = c/fc = 0.074948 m.
```

For the 25 mm X baseline, `u_x = 500/602.08 = 0.83045`:

```text
tau_x = 0.025*u_x/c = 69.25 ps
phase_x = -2*pi*4e9*tau_x = -1.7405 rad = -99.72 deg.
```

The corresponding Y- and Z-baseline phases are approximately `-59.83` and
`-29.92` degrees. MUSIC uses these three independent relative phases to recover
signed 3D direction.

The initial pure-pursuit corrections exceed the rate limits, so after one
`0.1 s` update yaw changes by `2 deg` and pitch by `1 deg`. At `25 m/s`, the
first displacement is approximately

```text
[2.4981 0.0872 0.0436] m.
```

## 10. Troubleshooting

### Constructor/SystemInterface error

```matlab
clearvars
rehash path
which SourceModel3D -all
```

Only the extracted project copy should be first on the MATLAB path. Restart
MATLAB once if an older class is locked; do not use global `clear classes`,
which causes the unrelated warnings reported for `digraph`, Simulink and HDL
objects. Every
custom System object in this package has an explicit `setProperties`
constructor for R2024a.

### Model builds but does not turn

Check the `Detection_Valid` display. If it stays zero:

- increase `P.Source.PowerdBm`;
- ensure `P.Candidate.BW_MaxHz` includes the source bandwidth;
- reduce `P.Candidate.MinSNRdB` carefully;
- check that the signal lies inside the sampled complex-baseband span.

### Azimuth moves in the opposite direction

Run `verify_doa_direction`. It checks positive and negative elevation with a
known array manifold. Also confirm that an older `DOAEstimator4Ch.m` is not
earlier on the MATLAB path.

### Elevation cannot become negative

Confirm that `P.Antenna.Positions` contains a Z-axis baseline and that
`P.DOA.ElScanRange = [-60 60]`. A planar four-element array is physically
ambiguous in elevation sign.

### Dashboard does not appear

Run manually after simulation:

```matlab
plot_simulink_results
```

If it reports a missing variable, confirm that the To Workspace blocks were
not removed and that the simulation was run in the same MATLAB workspace.
